# M01 管理

计划分支：`module/management`。需求来源：原 F06，以及 F11、F13 中的画板入口。细分需求编号：M01.01 至 M01.05。

本模块负责应用主页和画板目录，组织创建、打开、切换、分类、复制、回收和项目导入。画板的图片、文字、笔迹与关系数据由相应编辑模块维护。

## 代码目录与独立设计

统一采用 Flutter + Dart。计划代码目录为 `packages/thinkpaint_management/`，公开入口为 `lib/thinkpaint_management.dart`，私有实现放在 `lib/src/`，本模块验证放在 `test/`。这些代码目录在后续工程任务中建立。

本模块独立设计自己的页面、面板、对话框、工具与局部状态，设计资料按需要放在 `docs/design/M01/`。M10 统一主题、外壳、导航与焦点；模块通过页面、面板、工具和设置贡献接入，具体布局和交互由本模块细化并审阅。

静态依赖只使用两个共享协议包和本模块依赖，功能包之间不互相 import。提供：BoardNavigationPort、ManagementPageFactory。消费：ProjectRepositoryPort、CatalogRepositoryPort、SaveCoordinatorPort、ViewportPort、ToolRuntimePort、SystemAccessPort、SearchPanelFactory、SettingsPort。

依据：[技术决定](../architecture/PLATFORM_DECISION.md)、[工程结构](../architecture/PROJECT_STRUCTURE.md)、[共享接口](../architecture/SHARED_CONTRACTS.md)、[模块依赖](../architecture/MODULE_DEPENDENCIES.md)、[独立界面设计](../architecture/UI_DESIGN_GUIDE.md)。

## 职责边界与协作接口

M01 提供画板列表资料、当前画板标识、打开或切换画板请求，以及目录变化通知。主页包含画板缩略图、名称、分类、收藏和最近打开入口，页面本身由 M01 维护；M10 提供承载页面的应用外壳和导航容器。

M09 提供项目创建、读写、复制、导入、回收和恢复能力，并报告资源、格式与保存状态。M01 组织这些操作的入口、确认、进度和结果；实际文件、资源以及恢复数据的处理由 M09 执行。画板切换必须等待 M09 对当前编辑状态给出可继续的结果。

M04 提供视图状态的读取和恢复，M05 使用 M01 的画板资料建立索引并发起跨画板打开请求。跨模块数据标识、事件和操作约定见[模块协作约定](../MODULE_CONTRACTS.md)。需求总览见[项目需求](../REQUIREMENTS.md)，依赖和分支安排见[开发计划](../DEVELOPMENT_PLAN.md)。

## M01.01 应用主页与最近画板

**详细功能描述：**主页以画板卡片或列表展示可打开的画板，包含名称、缩略图、最近打开信息和收藏状态，并提供清楚的新建、导入与搜索入口。最近画板记录成功打开的项目；只在列表中预览或打开失败时，不写入成功打开记录。

缩略图与实际项目对应，项目发生变化后按共享规则更新。文件移动、访问失败或项目损坏时展示对应状态与处理入口，不把无法读取的画板显示为空白新画板。列表显示状态与项目内容分开维护。

**验收条件：**

- 新建、打开和编辑画板后，主页名称、缩略图和最近记录对应正确项目。
- 切换列表显示方式及重新启动应用后，收藏和排序设置正确保留。
- 无法访问的画板具有明确状态；打开失败不会生成重复画板或覆盖原项目。
- Windows 和 Android 的主页均能通过键鼠或触控完成主要管理操作。

## M01.02 新建、打开与切换画板

**详细功能描述：**提供新建空白画板、打开目录中已有画板和在多个画板之间切换的操作。每个新画板取得独立稳定标识，只有项目创建成功后才作为正常画板加入目录。

切换前向 M09 查询并处理当前保存状态，切换过程中明确展示正在打开、正在保存或失败的状态。目标打开成功后更新当前画板；保存或打开失败时保留可继续处理的当前编辑上下文，明确给出失败原因与下一步入口。

对象、工具状态和视图状态按约定分别归属，切换画板不会把上一画板的内容、选区或临时编辑误带到下一画板。

**验收条件：**

- 连续新建、切换和重开不同画板，各自对象、名称、资源和当前标识正确。
- 模拟创建失败、打开失败和保存失败时，状态与错误来自实际操作结果，目录不出现虚假成功记录。
- 切换过程中发起重复打开请求时，最终当前画板明确且不存在重复加载的编辑会话。
- 当前画板有文字编辑、笔画或其他尚未结束的操作时，按共享输入和保存规则结束、取消或阻止切换。

## M01.03 命名、分类、收藏与排序

**详细功能描述：**支持重命名画板、建立分类文件夹或标签、加入收藏，以及按名称、最近打开或修改信息排序。分类和排序操作作用于画板目录；原项目中的对象坐标、内部归属与关系不随目录调整而变化。

画板名称可以重复，但操作始终依据稳定画板标识执行。重名时界面提供足够的分类、位置或时间信息帮助区分。目录信息发生变化后向 M05 发送可索引的更新资料。

**验收条件：**

- 两个同名画板可分别重命名、收藏和分类，操作命中正确项目。
- 改名和分类后，最近记录、搜索结果与当前画板标题同步更新。
- 分类、收藏及排序重新启动后正确保留，单独导入项目仍可加入新的目录。
- 目录整理不改变画板内部对象和关系，失败时不显示未完成的结果。

## M01.04 独立复制与画板回收站

**详细功能描述：**提供复制画板，生成可独立编辑的新项目，并完整保留图片、笔迹、文字、档案盒、内部连接、批注和必要显示设置。副本使用新的画板标识；对象标识及内部引用按照共享复制规则统一处理。

删除画板时先进入回收站，支持查看和恢复。清空回收站作为单独且明确的操作展示影响范围，由 M09 执行真正移除。涉及已打开画板时先处理当前保存状态，再根据实际回收结果更新目录和当前页面。

M01 展示复制、回收和恢复的结果，M09 保证项目与资源一致。资源复用或物理存储方式不能使修改、删除副本影响原画板。

**验收条件：**

- 复制包含混合对象和内部关系的画板，修改副本后原画板内容正确保留。
- 副本中的连接、图片批注和档案盒成员均指向副本内正确对象。
- 删除后可恢复完整项目；恢复成功才重新出现在正常画板列表中。
- 复制、回收或恢复中断时，目录状态与 M09 的有效项目状态一致，并明确报告失败。
- 清空回收站与普通回收具有不同入口和明确的影响说明。

## M01.05 项目导入入口与视图恢复

**详细功能描述：**提供从系统文件选择、打开方式或分享入口导入可编辑项目的流程。M09 检查格式版本、资源完整性并执行导入，成功后 M01 将项目加入画板目录。单张图片或一组图片导入画板属于 M03，通过明确入口与项目文件导入区分。

导入项目与已有画板标识发生冲突时，按共享导入规则创建可区分的目录项并维护引用，展示实际处理结果，不以同名或同标识为理由静默覆盖项目。

每个画板保留上次有效查看位置和缩放比例。打开完成后请求 M04 恢复对应视图；没有已有视图的新画板使用规定的初始视图。视图移动本身不改变对象坐标，也不混入内容编辑撤销。

**验收条件：**

- 同一项目经 Windows 和 Android 的项目入口导入后，目录、资源和编辑内容正确。
- 错误格式、资源缺失和不支持版本明确报错，原项目及目录中其他项目保留。
- 导入同名或标识冲突项目时，结果可辨认且不覆盖已有项目。
- 在相距较远的位置查看不同画板后切换回来，各自视图恢复正确。
- 新画板、已保存视图和无效视图状态均按约定处理，并能由 M04 提供可见的有效视图。

## 模块完整验收

通过主页创建、命名、分类并收藏多个画板，分别加入真实图片、中文文字和笔迹，再进行切换、复制、回收、恢复和跨端项目导入。核对每个画板的内容、关系、缩略图、目录资料及视图状态。保存或打开失败的场景必须验证实际目录与当前会话状态。

M01.01 至 M01.05 的验收全部通过，且与 M04、M05、M09、M10 的集成结果有记录后，本模块才记为完成。只展示静态主页、模拟项目操作或尚未接入真实保存的管理界面不能作为完整交付。
