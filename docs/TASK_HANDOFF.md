更新日期：2026-10-19。统一技术路线为 Flutter + Dart + 自定义绘制画布。

每模块由独立对话负责，在对应分支和 worktree 中细化自己的界面与功能，再按实际授权进入实现。已有模块成果和授权按其实际记录保留。

本轮更新工程与协议规划、模块目录和任务说明。后续模块设计任务可修改自己的任务卡、`docs/design/Mxx/` 和本模块需求细化，保留原编号与验收。当前公共规划不启动功能代码、工程生成或依赖安装。

## 目录和基线核对

代码责任目录为 `packages/thinkpaint_<模块>/`，具体名称见工程结构。公开入口与私有 `lib/src/` 分开。应用位于 `apps/thinkpaint/`，公共协议位于两个共享包，均由装配或相应主责维护。

模块先核对分支、工作目录、基线和已有改动，已有正确 worktree 直接复用。共享架构文档在管理仓库更新时，不自动覆盖模块分支；发布同步由相应授权安排，不能重设正在使用的分支或覆盖未提交工作。

M01～M04 已存在独立 worktree 和设计成果。主仓库任务卡提供公共架构补充，各模块完整业务方案、候选、审阅与授权记录继续由其自身任务卡维护。主分支发布不代表这些独立成果已经合入主分支。

## 模块任务卡

任务卡使用 `docs/tasks/M01.md` 等路径，记录：

- 模块、负责人、分支、独立目录、真实基线与当前授权。
- 本轮细项、计划代码目录、允许修改文件和设计资料。
- 提供与消费的公共接口、接口版本及真实实现状态。
- 本模块功能与界面方案、必要原型、审阅和采用决定。
- 联合操作的参与方、状态变化、失败取消、保存和撤销要求。
- 验收场景、固定样例、真实设备、实际结果与证据。
- 阻塞项、接口变更请求、剩余问题和下一步。

## 精细化设计流程

按本模块需求研究合适的已有产品与组件，为实质性方向给出选择、代价和推荐，在模块对话中审阅。记录采用方案后细化流程和视觉稿，补齐输入、空内容、加载、错误、取消和恢复状态。

模块内部界面由模块维护，通过公共 UI 贡献接入。跨模块行为、公共主题角色、路由或接口变化先协调。具体结构可按实际需要拆分，避免预先建立空目录、通用执行器或多份状态。

## 实现前置

实现需要实际可构建工程、最小协议包和类型注册入口，以及对应对话的明确授权。文档中的接口签名不代表可调用实现，目录树也不代表工程已经生成。

功能包之间不直接 import，通过构造参数取得共享端口。新的类型同时提供数据、编解码、几何、绘制、搜索与引用适配。每个完整编辑通过 M07 事务，跨模块操作单独验收。

## 交付

第一行写本轮完成状态，随后给出模块和细项、真实分支目录基线、文件差异、设计审阅结果、接口影响、实际验证与证据、剩余事项和对外状态。

设计完成、实现完成、真实集成和设备验收分别记录。提交、推送、合并、删除和发布按当前对话授权执行。可直接使用 [十模块任务说明](MODULE_TASK_PROMPTS.md)。
