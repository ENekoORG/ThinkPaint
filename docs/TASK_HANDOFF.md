# ThinkPaint 模块开发交接

更新日期：2026-10-19。

每个功能类别由独立开发对话负责，在对应 `module/` 分支与独立工作目录开发。需求细项作为领取、验证和增量交付单位，不按原阶段任务安排。

## 本轮任务范围

十个模块分支已经建立，任务卡存放在 `docs/tasks/M01.md` 至 `docs/tasks/M10.md`，每模块可直接复制的说明见 [模块任务说明](MODULE_TASK_PROMPTS.md)。

当前领取范围为模块开发准备：复核需求、拆分实施次序、提出接口与联合验收计划，只修改自己的任务卡。允许检查并创建分配的独立 worktree，功能代码、工程创建和开发依赖安装须等待统一技术决策与后续实现授权。模块准备说明不授予提交、推送、合并或发布权限。

## 开始前阅读

阅读 [项目工作约定](../AGENTS.md)、[当前进度](../PROGRESS.md)、[功能分类](REQUIREMENTS.md)、[按功能块开发的计划](DEVELOPMENT_PLAN.md)、[模块协作约定](MODULE_CONTRACTS.md)，再读本模块需求及实际依赖接口。

确认 `main` 已有获授权建立的初始提交，核对自己的分支、独立目录、基线、接口版本及工作区改动。发现其他任务改动、接口矛盾或未具备工程条件时，报告实际状态，由管理对话安排。

## 模块任务卡

管理对话在 `docs/tasks/M01.md` 等路径建立模块任务卡，实际领取时填写以下信息。

- 类别、负责对话、需求文件与模块分支。
- 独立工作目录、真实基线提交和已集成接口版本。
- 当前授权范围，分别写明实现、验证、提交、推送和合并。
- 实际代码目录、允许修改的文件、公共文件责任人。
- 本轮领取的细项，例如 M03.01 至 M03.03。
- 每个细项的详细目标、验收、真实设备或固定输入、证据位置。
- 依赖接口、协作模块、已有结果和等待的真实对接。
- 联合场景、发起方、参与方、取消失败行为与通过条件。
- 细项状态、重要决定、实际结果、剩余问题及下一步。

旧 F 编号可写在来源栏，领取和完成状态以当前 M 类别及细项为准。

## 发给独立开发对话的说明

负责分配的功能类别，先阅读公共文档、本模块需求和任务卡。核对实际分支、目录、基线、接口和允许修改范围，列出此次领取的细项、实施步骤和验证方法。

本轮先在自己的任务卡整理模块方案、接口需求、联合场景、设备与验收计划。后续获得实现授权后，在本模块目录内实现私有逻辑、界面和类型适配，通过共享接口与其他模块协作。开始前读取相关文件，不自行选用另一套框架、对象模型或项目格式。公共接口不满足时，说明需求及受影响模块，由管理对话安排主责模块调整。

可以独立交付已有依据的模块能力；尚未真实对接的细项记为待集成，缺少设备的记为待设备验证。不得用空接口、模拟界面或吞掉异常代替完整交付。

完成一组细项后提供实际变更和验证证据，再安排增量集成。根目录进度由管理对话维护，本对话更新自己的模块任务卡。

## 图片模块交接示例

负责 M03 图片类别，计划分支 `module/images`。阅读 M03.01 至 M03.07，独立完成导入显示、裁剪多实例、批量摆放、档案盒和图片批注。

与 M09 对接真实资源，M07 对接对象和事务，M04 对接显示坐标，M08 对接关系改接，M02、M06 对接批注内容，M05 对接搜索展开。档案盒收纳预览确认后改接盒整体，支持一次撤销、回环及保存往返；拖出图片保留盒连接。

实际工作目录、基线和代码范围由领取时的任务卡提供。接口已定的细项可分别推进，联合行为与相应模块一起验收。

## 工程装配交接

工程装配使用横向分支 `integration/assembly`，统一主技术路线、代码目录、公共接口落位、构建和模块注册。M04、M07、M09、M10 分别负责自己的共享接口，内容模块参加类型适配约定。

有实质性技术路线选择时，给出 2 至 3 个方案、代价与推荐，由项目所有者选择后执行。原型和样例用途明确，实际硬件验证与算法单测分别记录。

## 开发交付内容

- 完成状态，以及未完成、未对接或未验证的具体细项。
- 模块与细项编号、实际分支、独立工作目录和真实基线。
- 已提交版本，或未提交改动的准确文件与差异。
- 实际行为、主要文件、原因及对其他模块的影响。
- 实际设备、固定输入、命令、退出码、重要输出与证据。
- 接口、对象关系、保存兼容及联合操作结果。
- 剩余问题、接口请求和下一步。
- 按授权执行的提交、推送、合并或对外操作状态。

管理对话审查后安排增量集成和受影响验证，再更新总体进度。模块完成与整软件完成分别记录。
