# ThinkPaint 技术路线决定

更新日期：2026-10-19。架构版本：0.1。

## 统一路线

ThinkPaint 采用 Flutter + Dart + 自定义绘制画布，同时面向 Android 和 Windows。主要界面、对象逻辑与画布呈现共用，平台特有能力通过受控适配接入。

工具链目标为 Flutter 3.47.5，Dart 使用该发行版捆绑版本。建立工程时记录实际 Flutter、Engine、Dart、Android SDK 与 Windows 构建工具版本；Pub workspace 要求 Dart 3.6 或更高。这里的版本是初始验证目标，设备兼容与性能结果按实际验证记录。

候选比较与来源保留在 [技术路线候选](../TECHNOLOGY_OPTIONS.md)。后续工程和接口按本决定执行。

## 工程原则

- 一个 Flutter 应用承载十个模块，Android 和 Windows 使用同一应用代码与项目语义。
- 每个模块有独立 package、公开入口、私有实现、测试和设计资料。
- 两个共享协议包分别提供纯 Dart 数据与服务约定、Flutter 界面与绘制约定。
- 模块通过构造参数取得窄接口，应用负责装配。模块业务流程仍由所属模块维护。
- UI 状态优先使用 Flutter 的 Listenable/ValueListenable，异步接口使用 Future/Stream；按实际需要拆分控制器与 Widget。
- 根 workspace 统一依赖解析和锁文件。新增第三方依赖、共享接口或平台配置由主责提出，装配工作统一处理。

## 模块独立设计

每个模块负责自己的页面、面板、对话框、工具界面、内部状态和交互细节，在 `docs/design/M01/` 至 `docs/design/M10/` 内按需要形成调研、视觉稿、流程和验收记录。

模块对话组织本模块方案审阅。改变产品方向的方案先给出选择、代价和推荐，由项目所有者选择。局部设计遵守公共主题、导航、焦点、输入与数据协议；改变跨模块行为时协调相应主责。

M10 提供外壳、公共主题、导航承载与焦点规则，各模块通过页面、面板、工具和设置贡献接入。具体页面布局由模块设计，公共外壳不接管全部页面设计。

## 已有界面约束

M01 采用暖纸色、文件夹与收藏的画板主页，支持卡片和紧凑列表，Android 以平板为主要设计对象，同时保留窄屏适配。侧栏底部依次为回收站、独占一行的设置入口，分类滚动时底部入口可见，返回后恢复浏览状态。

M01 维护主页设置入口，M10 承载设置页与公共偏好，各设置内容按所属模块提供。上述约束来自管理模块独立方案，现有 worktree 中的完整业务和审阅记录由该模块继续维护。

## 绘制和输入原则

画布采用 Flutter 自定义绘制。M04 处理视图、坐标、可见范围、呈现调度和显示缓存，内容模块提供自身绘制与几何适配。连续笔迹使用活动预览，完成后作为完整编辑提交。

M10 从实际平台采集标准指针和设备能力；压力、倾斜或笔按钮缺失时明确表示缺失。针对目标 Windows 数位板及 Android 平板验证压感、笔触摸共存、侧键、橡皮和取消输入，再决定必要的原生补充。

图片原图与资源引用归 M09，显示尺寸选择与图像显示缓存归 M04，图片裁剪和实例语义归 M03。绘制过程只消费已准备的显示数据，资源读取与解码在绘制之前安排。
