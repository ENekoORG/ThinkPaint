# ThinkPaint 按功能块开发与分支计划

文档版本：0.2。更新日期：2026-10-18。

本计划以十个软件功能块组织开发，取代原按阶段排列的开发计划。旧任务顺序和旧分支安排停止作为工作依据。每个类别由一个独立开发对话负责，类别内按细项持续交付。

## 独立开发的交付方式

每类拥有独立实现目录、界面或适配、测试和任务记录。类别内部先交付可以真实验证的私有能力，再接入公共接口，最后完成联合场景。模块不必等其他类别的全部功能完成后才开始。

各模块之间通过 [协作约定](MODULE_CONTRACTS.md) 互相调用。尚未完成真实对接的细项记录为待集成，缺少设备的记录为待验证。只有接口空实现或单独演示时不能把整项功能记为完成。

## 工程与接口准备

仓库目前没有初始提交或功能工程。开发分支创建前，需要按授权建立文档初始提交，使 `main` 具有真实基线。实际代码目录在技术路线确定后统一记录。

工程装配由管理对话统筹，使用横向分支 `integration/assembly` 处理工程创建、共享接口落位、模块注册、构建配置和联合检查。它服务全部类别，不作为额外的软件功能类别，也不替代各模块实现。

存在实质性技术路线取舍时，先向项目所有者呈现 2 至 3 种选择、代价与推荐，取得选择后执行。十个类别使用同一套主技术路线和项目格式，不能各自建立不兼容应用。

M04、M07、M09、M10 分别固定坐标视图、对象事务、项目资源、输入与外壳的最小接口，各内容模块共同评审注册和适配方式。实际接口需要记录负责人、版本、代码路径、输入输出、错误处理和样例。接口可用后，对应类别即可推进，不要求先实现全部导航、保存导出或外观。

实际技术决策和接口说明分别存入 `docs/architecture/PLATFORM_DECISION.md`、`docs/architecture/SHARED_CONTRACTS.md`。这两个文件由获授权的工程装配工作创建；当前协作语义以现有模块约定为依据。

## 各类内部开发顺序

每类按下表安排自己的工作，属于模块内部的推荐顺序。涉及其他模块的具体行为按接口可用情况接入，记录实际前置条件。

| 类别 | 类别内推进顺序 | 必须联合验证的能力 |
| --- | --- | --- |
| M01 | 首页列表 → 创建打开切换 → 分类收藏 → 复制回收 → 导入与视图恢复 | 项目读写、搜索入口、保存失败时切换、导航恢复 |
| M02 | 画笔配置 → 笔和鼠标路径 → 压感和平滑 → 两种擦除 → 自由箭头 | 实际设备、通用选择撤销、绑定箭头和图片批注 |
| M03 | 导入资源与显示 → 裁剪和多实例 → 批量摆放 → 盒浏览 → 收纳事务 → 图片批注 | 资源可靠保存、连线改接、附着变换和搜索展开 |
| M04 | 坐标视图 → 内容注册与命中 → 可见绘制 → 导航 → 边缘平移与查看条件 | 全部真实内容类型、远坐标、导出和资源释放 |
| M05 | 索引协议 → 增量索引 → 查询筛选 → 结果界面 → 定位与索引恢复 | 实际内容修改、跨画板打开、折叠盒和隐藏对象 |
| M06 | 编辑状态与中文输入 → 样式便签 → 布局键盘 → 共享编辑 → 字体兼容 | 线条标签、图片批注、保存往返和双端输入 |
| M07 | 身份归属和事务 → 选择 → 变换复制删除 → 层次分组 → 区域排版 | 混合类型、关系与批注恢复、收纳一次撤销 |
| M08 | 绑定与关系模型 → 端点随动和回环 → 来源备注 → 标签状态 → 专注查看 | 路径编辑、收纳改接、资料搜索与筛选导出 |
| M09 | 格式和资源接口 → 一致保存 → 自动保存恢复 → 跨端往返 → PNG/PDF | 各类型编解码、真实故障、实际呈现和筛选范围 |
| M10 | 外壳和标准输入 → 工具与输入优先级 → 偏好设置 → 外观 → 双端生命周期 | 中文输入、实际笔设备、导航手势、后台保存 |

## 可以同时推进的工作

- 管理、文字编辑、绘图算法、图片专用逻辑、查询算法和关系计算可以在接口约定后分别推进；各自补充真实模块接入。
- 画布与对象编辑分开维护，前者负责坐标和呈现，后者负责公共对象和编辑操作。内容模块只通过适配器接入。
- 保存模块按类型注册编解码，各内容模块维护自身专用数据；新类型接入不要求保存模块理解其全部编辑细节。
- 标准输入采集由界面与设备模块统一提供，绘图、画布和文字分别处理自己的动作，避免各自读取并重复消费同一设备事件。
- 共享接口修改先安排主责模块更新，再通知调用方调整。接口不稳定时先推进不受影响的细项，并明确挂起受影响条目。

## 联合操作责任

| 场景 | 发起与界面 | 协作方 | 联合通过条件 |
| --- | --- | --- | --- |
| 新建打开与切换画板 | M01 | M09、M04、M10 | 项目实际读写、保存状态和视图恢复正确 |
| 图片批注 | M03 | M02、M06、M07、M04 | 内容与图片变换、裁剪、解除绑定和撤销一致 |
| 收纳图片并改接连线 | M03 | M08、M07、M09、M04 | 预览确认、回环、取消、一次撤销和重开均正确 |
| 搜索盒内或隐藏内容 | M05 | M01、M03、M07、M04 | 打开画板、展开容器、明确临时显示并定位 |
| 专注与资料筛选 | M08、M05 | M04、M07 | 查看方式不改变真实对象、归属或绑定 |
| 项目往返与导出 | M09 | 各内容模块、M04、M05、M08、M10 | 资源和关系完整，当前条件及完整内容输出明确 |
| 后台取消与恢复 | M10 | 当前工具模块、M07、M09 | 工具正确结束或取消，保存真实状态可恢复 |

联合验收按能力安排；某一类别完成自己的部分后即可申请对接，不集中等待全部模块完工。联合结果写在相关模块任务记录中，管理对话维护总体结果。

## 工作目录与代码归属

一个类别对话使用一个模块分支和独立 Git worktree，即同仓库的独立工作目录。禁止并行对话在同一个目录切分支。管理对话分配真实路径和基线，其他对话不占用同一目录。

代码按模块设独立目录，实际名称和语言目录在工程装配时确定。主程序装配入口、构建配置和共享接口文件由装配负责人统一维护；M10 实现外壳模块，不另外创建工程。模块通过注册接入，新增类型不应要求各对话同时改同一个主文件。

需求索引、计划、公共协作约定和根目录进度由管理对话维护。模块对话维护自己的任务记录；修改其他模块或公共约定前报告影响，由管理对话协调责任人。

## 分支更新与增量集成

`main` 保存已审查且相应验证通过的集成版本。各 `module/` 分支记录真实基线和依赖接口版本，完成一组细项后提交可检查的变更与证据，按授权安排增量合入和联合检查。

其他模块合入后，各模块按授权更新到最新基线，重跑受影响检查。长期独立开发时定期同步已集成接口，避免到最后一次性合并。版本不兼容或内容冲突由相应主责模块处理，不能只解决文本冲突就报告兼容。

Git 提交、推送、合并、分支删除和公开发布按当前对话授权执行。本次仅规划分支，实际模块分支尚未创建。

## 任务与完成状态

模块任务卡采用 `docs/tasks/M03.md` 等路径，内部按 M03.01 等细项记录负责人、分支、实际目录、基线、可改路径、接口版本、验收和证据，格式见 [任务交接](TASK_HANDOFF.md)。

细项状态可为未领取、开发中、自测通过、待集成、待设备验证或已验收。模块完成要求本模块全部条目通过，关联联合场景有真实结果。单独算法或界面通过后保留具体状态，不提前将整个软件标为完成。

## 完整软件验收

使用固定设备和负载覆盖十类功能，验证混合编辑、关系线、档案盒、搜索、恢复、跨端往返和导出。性能目标在测试前确定，实际值与目标分开记录。设备不足、对接缺失或失败的条目持续列出，按根因修复后复验。

验收记录使用 `docs/validation/`，按模块和联合场景命名。发行包、依赖许可证、远程推送和公开发布由管理对话另行安排授权。
